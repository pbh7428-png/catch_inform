# 계획 검토 결과

## 1. 종합 판정: **결정 대기**

구현에 필요한 핵심 사항(데이터 출처, 누락 처리, 실행 시간, CSV 컬럼, 완료 기준)이 모두 "미정"이라, 지금은 무엇을 만들지와 언제 끝났는지를 판단할 수 없습니다. 목표와 범위 자체는 작고 명확해서, 아래 결정만 내려지면 바로 시작할 수 있습니다.

이 검토에서 외부 자료는 조회하지 않았습니다. 시장 제도와 데이터 출처에 관한 내용은 제 배경지식이며, 확인된 사실이 아니라 조사할 항목입니다.

## 2. 막는 문제

| 위치 | 문제 | 이유 |
|---|---|---|
| 미정 › 데이터 출처와 이용 조건 | 출처가 없음 | 인증 방식, 호출 한도, 데이터 제공 시각, 응답 형식이 모두 출처에 달려 있어 실행 시간·컬럼·실패 처리도 함께 막힙니다. |
| 미정 › 완료 기준 | 확인 가능한 완료 기준이 없음 | "모아서 저장한다"만으로는 한 번 성공하면 끝인지, 며칠 연속 무인 실행이 되어야 하는지 알 수 없습니다. |
| 목표 › "10개 종목" | 종목 목록과 식별자가 없음 | 어떤 종목인지, 6자리 종목코드로 관리하는지 정해져야 입력과 검증 대상이 생깁니다. |
| 문서 전체 | 실행 환경 언급이 없음 | 미정 목록에도 빠져 있습니다. 개인 PC(꺼져 있으면 누락), 상시 서버, 클라우드 스케줄러 중 무엇이냐에 따라 누락 처리 설계가 달라집니다. |

## 3. 중요한 개선점 (우선순위 순)

1. **"종가"의 정의를 고정하세요.**
   - 정규장 종가인지, 시간외 단일가나 대체거래소(넥스트레이드) 가격을 포함하는지 정해야 합니다.
   - 수정주가인지 원주가인지도 정해야 합니다. 액면분할이나 권리락이 생기면 과거 값과 불연속이 생깁니다.
   - 단위(원, 정수)와 기준일(거래일, KST)을 컬럼으로 명시하는 것이 좋습니다.

2. **출처 후보별로 제공 시각과 약관을 확인하세요.** 아래는 모두 조사할 항목입니다.
   - 공공데이터포털 주식시세 API: 당일이 아니라 다음 영업일에 갱신되는 것으로 알고 있습니다. 사실이면 "장 마감 후 당일 수집" 목표와 충돌합니다.
   - KRX 정보데이터시스템 Open API: 이용 신청과 승인 절차, 당일 데이터 제공 시각을 확인해야 합니다.
   - 증권사 Open API(예: 한국투자증권): 계좌 필요 여부와 토큰 만료 주기를 확인해야 합니다.
   - 비공식 라이브러리나 포털 스크래핑(pykrx, 네이버 금융 등): 약관상 허용 여부와 구조 변경으로 깨질 위험을 확인해야 합니다.

3. **"평일"을 "거래일"로 바꾸세요.** 공휴일, 연말 휴장일, 임시 휴장이 있고, 수능일처럼 마감 시각이 늦춰지는 날도 있는 것으로 압니다(확인 필요). 휴장일에 실행되면 빈 행인지, 전일 값인지, 기록 없음인지 정해야 합니다.

4. **누락과 실패 처리를 경우별로 정하세요.**
   - 일부 종목만 실패했을 때: 성공분만 저장할지, 전체를 실패로 볼지.
   - 거래정지 종목: 직전 종가를 반환하는 출처가 많아, 그날 거래가 있었는지 구분되지 않을 수 있습니다.
   - 실행 자체가 빠진 날: 나중에 과거 날짜를 채울(백필) 것인지. 출처가 과거 일자 조회를 지원해야 가능합니다.
   - 실패를 소유자가 어떻게 알게 되는지(로그 파일, 알림 등). 알림이 없으면 몇 주간 누락을 모를 수 있습니다.

5. **CSV 저장 규칙을 정하세요.**
   - 한 파일에 누적할지, 날짜별 파일로 나눌지.
   - 같은 날 재실행 시 중복 행을 어떻게 막을지(날짜+종목코드를 키로 덮어쓰기 권장).
   - 종목코드는 문자열로 저장해야 앞자리 0이 유지됩니다(예: `005930`).
   - 엑셀로 열 계획이면 인코딩(UTF-8 BOM)을 정해야 한글 종목명이 깨지지 않습니다.

6. **범위의 "가격"이 모호합니다.** 목표는 "종가"인데 범위는 "가격"입니다. 종가만인지, 시가·고가·저가·거래량도 포함하는지 한 단어로 통일하세요.

7. **문서 제목이 내용과 다릅니다.** 제목은 "테스트 계획"이지만 내용은 프로젝트 계획이고 테스트 항목은 없습니다. 의도한 것이 테스트 계획이라면 검증 항목이 통째로 빠져 있는 것입니다.

## 4. 프로젝트 소유자가 결정할 질문

1. 대상 10개 종목은 무엇이며, 목록은 고정입니까, 설정 파일로 바꿀 수 있어야 합니까?
2. 당일 저녁에 꼭 받아야 합니까, 다음 영업일 오전에 받아도 됩니까? 이 답이 출처 선택을 좌우합니다.
3. 어디서 실행합니까(개인 PC, 상시 서버, 클라우드)? PC라면 꺼져 있던 날은 어떻게 처리합니까?
4. 증권사 계좌나 API 키 발급이 필요한 출처도 괜찮습니까, 무료·무인증만 원합니까?
5. 종가는 정규장 원주가 기준으로 충분합니까?
6. 수집 시작 이전의 과거 데이터도 필요합니까?
7. CSV를 주로 무엇으로 봅니까(엑셀, 스크립트, 다른 도구)?
8. 실패 시 알림이 필요합니까, 로그만 남기면 됩니까?

## 5. 문구 및 완료 기준 수정 제안

**목표 문구** (괄호 안 값은 소유자가 결정):

> 국내 상장 주식 10개 종목(종목코드 목록은 설정 파일에 명시)의 **정규장 종가(원, 원주가)**를 **KRX 거래일마다** 장 마감 후 (HH:MM KST)에 1회 수집해 CSV에 저장한다.

**CSV 컬럼 초안**:

> `date`(거래일, YYYY-MM-DD, KST), `code`(6자리 문자열), `name`, `close`(원, 정수), `fetched_at`(수집 시각, ISO 8601), `source`

**완료 기준 초안** (숫자는 예시이며 소유자가 확정):

> - 수동 실행 1회로 10개 종목의 당일 행 10개가 CSV에 기록된다.
> - 같은 날 다시 실행해도 `date`+`code` 기준 중복 행이 생기지 않는다.
> - 임의의 3거래일분 종가가 출처와 다른 공개 화면(예: 증권사 HTS)의 값과 일치한다.
> - 휴장일에 실행하면 행을 추가하지 않고 그 사실을 로그에 남긴다.
> - 일부 종목 조회가 실패하면 (정한 방식대로) 처리하고, 실패 종목과 사유가 로그에 남는다.
> - 연속 (5)거래일 동안 사람의 개입 없이 예약 실행이 성공한다.

**미정 목록에 추가할 항목**:

> 실행 환경, 대상 종목 목록, 종가의 정의(정규장·수정주가 여부), 휴장일 판별 방법, 실패 알림 방식, 백필 여부
