## 2. 발견 사항

- **중간 — `ticker_lookup.py:12`**  
  `find_ticker`는 입력에 `.strip().upper()`를 적용하지만, `upper()`는 한글에 변화를 주지 않습니다. 현재 지원 목록에는 `"나스닥"`만 있어 대소문자 변환이 필요한 한글 입력은 없지만, 작성자 의도인 “국내 주식 종목을 종목명이나 코드로 조회”와 구현이 맞지 않습니다. 실제 코드는 국내 주식이 아닌 S&P500·나스닥 ETF 두 항목만 지원합니다. 국내 종목을 입력하면 모두 `None`을 반환합니다. 국내 종목 조회가 의도라면 국내 종목명과 종목코드 데이터 및 검색 로직을 추가하고, 현재 두 ETF만이 의도라면 변경 의도와 문서 설명을 일치시켜야 합니다.

- **낮음 — `test_ticker_lookup.py:15-17`**  
  테스트는 `"나스닥"`의 정확한 표기만 확인합니다. `find_ticker`의 대소문자 무시 동작은 영문 `"S&P500"`에 대해서만 검증되므로, 한글 종목명에서도 같은 동작을 기대하는 요구가 있다면 테스트가 이를 확인하지 못합니다. 한글 표기 변형을 지원할 계획이라면 해당 입력과 기대 결과를 테스트에 추가해야 합니다.

## 3. 테스트 누락

- 국내 주식 종목명·종목코드 조회 결과를 검증하는 테스트가 없습니다. 현재 테스트는 S&P500과 나스닥 두 ETF만 다룹니다.
- `find_ticker`에 `None` 등 문자열이 아닌 값이 들어오는 경우의 처리도 테스트하지 않습니다. 다만 함수가 `str`을 받도록 선언되어 있어, 이 입력을 지원해야 하는지는 주어진 내용만으로 판단할 수 없습니다.

## 4. 확인하지 못한 부분

- 국내 주식 종목 목록을 제공하는 데이터나 기존 조회 로직이 다른 파일에 있는지는 주어진 변경 내용만으로 확인하지 못했습니다.
