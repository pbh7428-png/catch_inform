## 1. 종합 판정: **결정 대기**

현재 계획은 목적과 대략적인 첫 버전 범위를 제시하지만, 데이터 출처·이용 조건과 수집 성공을 판정할 기준이 정해지지 않았습니다. 이 두 가지는 데이터를 책임 있게 가져오고 결과를 신뢰할 수 있는지에 직접 영향을 주므로, 구현 전에 결정해야 합니다. 나머지 빈틈은 모두 착수를 막는 문제라기보다 계획을 구체화할 개선점입니다.

## 2. 막는 문제

- **데이터 출처와 이용 조건 — 문서의 ‘미정’ 항목:** 어떤 출처에서 가격과 종목명을 가져올지, 자동 수집이 허용되는지 확인되지 않았습니다. 출처와 이용 조건을 확인하기 전에는 수집 방식과 사용 가능성을 판단할 수 없습니다. 출처별 API 접근 조건·한도·비용은 조사 후 확정할 사항입니다.

- **완료 기준 — 문서의 ‘미정’ 항목:** 하루 수집 결과를 언제 성공으로 볼지 정해져 있지 않습니다. 종목별 누락을 허용하는지, 저장된 값을 어떻게 확인할지 기준이 없어 첫 버전의 완료 여부를 일관되게 판정하기 어렵습니다.

## 3. 중요한 개선점

1. **실행 시점과 ‘종가’의 의미를 구체화하세요.** ‘평일 장 마감 후 하루 한 번’만으로는 실행 시간과 가격 기준이 정해지지 않습니다. 휴장일·조기 종료일에도 실행할지, 종가가 해당 거래일의 공식 종가를 뜻하는지 계획에 밝혀야 합니다.
2. **누락·실패 처리를 정하세요.** 종목별 데이터가 없거나 출처에 접속할 수 없는 경우, 재시도할지·기존 CSV를 어떻게 보존할지·실패를 어떻게 알릴지 아직 알 수 없습니다.
3. **CSV 형식과 데이터 범위를 확정하세요.** 컬럼, 날짜 표기, 종목 식별 방법, 종목 10개의 선정·변경 방식이 미정입니다. 특히 종목명만으로는 동명 또는 이름 변경 사례를 구분하기 어려울 수 있으므로, 종목 코드가 필요한지는 소유자가 결정해야 합니다.
4. **실행 환경과 운영 방식을 기록하세요.** 어디에서 어떤 일정 실행 수단으로 작업할지, 저장 경로와 실행 결과를 어떻게 확인할지 계획에 없습니다. 이는 선택한 데이터 출처와 환경을 조사한 뒤 정하면 됩니다.
5. **보안·개인정보 위험은 현재 정보만으로 판단할 수 없습니다.** 계획에는 인증 정보나 외부 전송이 언급되지 않아 구체적인 위험이 확인되지 않았습니다. 사용할 출처에 인증이 필요하다면 비밀정보 보관·관리 방식을 정하고, 개인 데이터가 수집·전송되는지 출처와 실행 환경을 확인하세요.

## 4. 프로젝트 소유자가 결정할 질문

- 사용할 데이터 출처는 어디이며, 자동 수집과 CSV 저장을 허용하는 이용 조건·접근 한도·비용은 확인됐나요?
- 10개 종목은 무엇이며, 종목을 식별할 때 종목 코드도 저장할까요?
- 종가는 어떤 거래일과 출처 기준의 값을 뜻하며, 실행 시간과 휴장일 동작은 어떻게 할까요?
- 일부 종목 수집 실패나 전체 실행 실패 때 재시도·저장·알림은 어떻게 할까요?
- CSV 컬럼과 날짜 형식은 무엇으로 할까요?
- 한 번의 실행을 성공으로 판단할 최소 기준은 무엇으로 할까요?

## 5. 문구 또는 완료 기준 수정 제안

문서의 ‘미정’을 확정한 뒤, 완료 기준을 다음처럼 관찰 가능하게 적을 수 있습니다. 대괄호 항목은 프로젝트 소유자가 정해야 할 값입니다.

> **완료 기준:** 지정한 거래일과 출처 기준으로 대상 종목 [선정·식별 규칙]의 종가와 종목명 데이터를 수집해, 정한 CSV 컬럼과 날짜 형식으로 저장한다. 실행 결과에서 종목별 수집 성공·실패를 확인할 수 있으며, 일부 또는 전체 실패 시 [정한 재시도·저장·알림 규칙]을 적용한다.

이 제안은 기준을 구체화하기 위한 틀이며, 종목별 성공을 반드시 요구하거나 특정 실패 처리 방식을 전제하지 않습니다. 해당 정책은 소유자가 정해야 합니다.
