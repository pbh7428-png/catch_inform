# 보유 종목 데일리 뉴스 메일 — PRD/TRD

작성일: 2026-10-11

## 문제 정의

투자 중인 미국 주식 종목에 그날 어떤 뉴스가 있었는지 매일 한 번, 핸드폰에서도 확인하고 싶다. 종목마다 기사를 다 읽을 수는 없으므로 종목당 가장 많이 보도된 이슈 2개만 골라 한국어로 받아 본다. 사용자는 프로젝트 소유자 1명이다.

## 확정

- 대상: 미국 주식. 종목 목록은 설정 파일로 두고 사용자가 직접 고친다(초기 예시 `SPY`, `QQQ`).
- 선정: 조회수 대신 많이 보도된 이슈 상위 2개.
- 전달: Gmail로 발송한다(밖에서 핸드폰으로 확인).
- 언어: 한국어 번역·요약을 붙인다.

## 가능성 확인 결과 (2026-10-11)

| 항목 | 상태 | 내용 |
|---|---|---|
| Google 뉴스 RSS (`news.google.com/rss/search?q=...+when:1d`) | 확인 | 키 없이 응답. NVDA 기준 하루 70건 이상, 항목마다 제목·링크·발행 시각·언론사. 같은 이슈를 여러 언론사가 따로 실어서 보도 건수 계산에 적합. 조회수 필드는 없음. |
| Yahoo Finance RSS | 확인, 탈락 | 19건뿐이고 해당 종목과 무관한 기사가 섞임. |
| Finnhub 등 키 기반 API | 미확인 | 공식 문서로 확인 못 함. 첫 버전에서 쓰지 않음. |
| 기사 본문 | 사용 안 함 | RSS에는 제목만 있음. 본문 수집은 유료벽·약관 문제가 있어 제외. |

## PRD

**목적:** 하루 한 번 보유 종목별 주요 이슈 2개를 한국어 메일로 받아, 원문을 읽을지 30초 안에 판단한다.

**필수 기능**

1. 설정 파일의 종목별로 최근 24시간 뉴스를 수집한다.
2. 같은 이슈를 다룬 기사를 묶고, 보도한 서로 다른 언론사 수가 많은 순으로 2개를 고른다.
3. 이슈마다 대표 기사 제목의 한국어 번역, 묶인 제목들에 근거한 한 줄 요약, 언론사 수, 원문 링크를 보여준다.
4. 결과를 HTML 메일로 Gmail에 보내고, 같은 내용을 `output/YYYY-MM-DD.html`로 남긴다.

**제외:** 조회수, 기사 본문 요약, 주가·수익률, 국내 주식, 웹 서버, 온라인 배포, 매매 판단.

**완료 기준**

- [ ] 종목 파일에 티커를 추가·삭제하면 다음 실행 메일에 그대로 반영된다.
- [ ] 종목마다 이슈가 최대 2개이고, 각각 언론사 수·한국어 제목·요약·원문 링크가 있다.
- [ ] 메일의 언론사 수가 그날 RSS 원자료에서 손으로 센 값과 일치한다(종목 2개 표본 대조).
- [ ] 뉴스가 0건인 종목은 "최근 24시간 뉴스 없음", 수집 실패 종목은 "수집 실패"로 표시되고 다른 종목은 정상 출력된다.
- [ ] 번역이 실패하면 영어 원문 제목을 "번역 실패" 표시와 함께 보여준다(빈칸·지어낸 문장 없음).
- [ ] `--dry-run`은 메일을 보내지 않고 HTML 파일만 만든다.
- [ ] 메일이 핸드폰 Gmail 앱에서 가로 스크롤 없이 읽힌다.
- [ ] 메일 하단에 수집 시각(KST), 대상 기간, 출처(Google 뉴스 RSS), "요약은 제목만 근거로 함"이 적혀 있다.
- [ ] RSS 항목 일부를 읽지 못하면 그 종목에 "일부 수집 실패"와 건수를 표시한다("뉴스 없음"으로 뭉개지 않는다).
- [ ] 번역 응답이 빠지거나 형식에 맞지 않은 이슈는 "번역 실패"로 표시한다.
- [ ] 메일 발송이 실패하면 콘솔에 이유가 나오고 종료 코드가 1이며, HTML 파일은 남는다. 오류 문구에 앱 비밀번호가 나오지 않는다.
- [ ] 임계값을 바꾸면 같은 종목(NVDA, SPY, QQQ)의 실제 RSS로 묶음 결과를 다시 눈으로 확인하고 날짜를 코드 주석에 남긴다.

## TRD

**실행 환경:** 이 PC에서 `py daily_news.py` 수동 실행. Python 표준 라이브러리만 사용한다(설치 없음). 네트워크가 필요하다. 매일 자동 실행(작업 스케줄러)은 수동 실행이 안정된 뒤 따로 확인받고 등록한다.

**구성 요소** (저장소 루트. 기존 `ticker_lookup.py`는 리뷰 스킬 시험용이라 건드리지 않는다)

- `tickers.json`: `[{"ticker": "SPY", "name": "S&P 500 ETF", "keywords": ["S&P 500"], "exclude": ["I SPY"]}]`. `ticker`와 `keywords`가 검색어와 관련성 판정에 쓰이고, `exclude` 문구가 제목에 있으면 뺀다. `name`은 메일 표시용이다.
- `.env` (gitignore): Gmail 주소, 앱 비밀번호, 받는 주소.
- `news_fetch.py`: 종목별 RSS 요청·파싱(`urllib`, `xml.etree`). 발행 시각 기준 24시간 밖 항목 제거.
- `issue_cluster.py`: 제목 끝 ` - 언론사` 제거 → 소문자·불용어 제거 토큰화 → 토큰 자카드 유사도가 임계값 이상이면 같은 이슈로 묶음.
- `translate.py`: 선정된 이슈만 모아 한 번에 번역·요약 요청.
- `render.py`: 메일용 HTML(인라인 스타일, 단일 열).
- `send_mail.py`: `smtplib` SSL(465)로 Gmail 발송.
- `daily_news.py`: 전체 흐름과 `--dry-run`.
- `test_*.py`: 저장된 RSS 표본 XML로 네트워크 없이 검증.

**데이터 흐름:** `tickers.json` → RSS 수집 → 24시간 필터 → 이슈 묶기 → 상위 2개 → 번역·요약 → HTML → 파일 저장 → Gmail 발송

**핵심 규칙**

- 이슈 점수 = 묶음 안의 서로 다른 언론사 수(단위: 곳). 같은 언론사의 중복 기사는 1로 센다. 동점이면 최신 기사가 있는 묶음이 먼저다.
- 이 점수는 조회수가 아니라 언론 관심도를 재는 대체 지표다. 메일에 "N곳 보도"로 표기한다.
- 유사도 임계값은 0.3이다(2026-10-11 NVDA·SPY·QQQ 실제 RSS로 0.2/0.3/0.4 비교). 0.4는 같은 이슈가 여러 묶음으로 갈라졌고 0.2는 무관한 기사가 붙었다.
- 대표 기사 = 묶음 안의 다른 제목들과 유사도 합이 가장 큰 기사. 동점이면 먼저 발행된 기사. (처음 계획은 "가장 먼저 발행된 기사"였으나, 이어 묶인 주변 기사가 대표가 되는 경우가 있어 바꿨다.)
- 종목 무관 기사 제거: 제목에 티커(대소문자 구분, 단어 경계)나 `keywords` 문구가 없으면 제외한다. 시세·옵션·공시 목록 페이지 제목과 `exclude` 문구가 있는 제목도 제외한다.
- 알려진 한계: 이어 묶기 방식이라 주변 기사 한두 건이 딸려 와 언론사 수가 조금 늘 수 있다(2026-10-11 NVDA 묶음 23건 중 1건). GPT 코드 리뷰가 지적해 묶음 평균 유사도 방식을 시험했으나 같은 이슈가 3개로 쪼개져 상위 2개를 한 이슈가 차지했고, 평균이 낮은 기사를 떼는 방식은 정상 기사(0.15)와 주변 기사(0.12)의 차이가 작아 기준을 정할 수 없었다.
- `keywords` 작성 요령: 회사 이름이 일반 단어면(`Apple` 등) 무관한 기사가 잡힌다(2026-10-11 AAPL에서 "Big Apple" 식당 화재가 1위). `Apple Inc`, `iPhone`처럼 좁은 문구를 쓰거나 `exclude`로 뺀다.
- 같은 날 다시 실행하면 HTML 파일을 덮어쓰고 메일을 다시 보낸다(수동 실행이므로 중복 발송 허용).
- 외부로 나가는 자료: 기사 제목이 번역을 위해 Anthropic(Claude Code)으로 전송된다. 본문, 보유 수량, 금액은 다루지 않는다. 앱 비밀번호는 `.env`에서만 읽고 출력하지 않는다.
- 요약은 묶인 기사 제목들만 입력으로 쓴다. 제목에 없는 사실을 덧붙이지 않도록 프롬프트에 명시한다.
- 누락·실패는 종목 단위로 격리하고 문구로 표시한다. 0이나 다른 값으로 대체하지 않는다.

**검증:** `py -m unittest` 통과 → `--dry-run`으로 HTML 확인 → 종목 2개의 언론사 수를 RSS 원자료와 손으로 대조 → 실제 발송해 핸드폰에서 확인 → `code-review-gpt`.

**구현 순서**

1. 이 문서를 `plan-review-gpt`로 검토받고 반영한다.
2. 아래 가정 1·2를 작은 실험으로 확인한다.
3. 수집 + 이슈 묶기 + 테스트(영어 그대로 `--dry-run` 출력까지).
4. 번역·요약.
5. Gmail 발송.
6. (확인 후) 작업 스케줄러 등록.

## 가정과 미정

- **확인됨(2026-10-11), 번역 엔진:** `claude -p --model haiku`가 이 PC(Claude Code 2.1.296, Python 3.14.3)에서 동작했고 실제 이슈 4개의 번역·요약을 JSON으로 받았다. 구독 사용량을 쓰며 API 키는 쓰지 않는다. 사용량 한도에 걸리면 그날은 "번역 실패"로 표시된다.
- **확인됨(2026-10-11), Gmail 발송:** 앱 비밀번호 방식으로 `py daily_news.py`가 본인 주소로 발송에 성공했다(종료 코드 0). 핸드폰 Gmail 앱에서의 표시는 사용자가 확인할 항목이다.
- **확정(2026-10-11), 실행 위치:** PC 로컬. PC가 꺼져 있으면 그날 메일은 오지 않는다. GitHub Actions는 번역에 API 키와 비용이 들어 당분간 쓰지 않는다.
- **가정 4, Google 뉴스 RSS 이용 조건:** 개인용, 하루 1회, 종목 수만큼의 요청으로 쓴다. 약관의 자동 수집 허용 범위는 Google의 1차 문서로 확인하지 못했다(블로그 글 수준의 2차 자료만 "개인·비상업용 피드 리더 용도"라고 설명). 확인 전까지는 제목·언론사·원문 링크만 표시하고, 결과를 외부에 공개하거나 재배포하지 않으며, 원자료는 저장하지 않는다.
- **확정(2026-10-11), 자동 실행:** Windows 작업 스케줄러가 매일 08:00(KST)에 `run_daily.cmd`를 실행한다. 스케줄러로 한 번 돌려 번역과 발송이 되는 것을 확인했다.
- **미정:** ETF(`SPY` 등)는 종목 고유 뉴스가 적어 결과가 빈약할 수 있음(첫 실행 결과를 보고 검색어를 조정).
